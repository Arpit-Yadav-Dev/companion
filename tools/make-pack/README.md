# make-pack: turn video clips into a Companion character pack

This tool converts short AI-generated video clips into a `frames`-renderer
character pack: it extracts frames, removes the background, crops/aligns
everything to one shared bounding box, resizes, and exports transparent
WebP sequences plus a `pack.json`.

## Setup (once)

Dependencies live in the project's own virtualenv — never your system
Python, and ffmpeg comes from `imageio-ffmpeg`'s bundled binary, never
Homebrew's:

```
python3 -m venv tools/.venv
./tools/.venv/bin/pip install -r tools/make-pack/requirements.txt
```

If your clips aren't on a solid-color background and you need `--bg
rembg` (see below), also run:

```
./tools/.venv/bin/pip install -r tools/make-pack/requirements-rembg.txt
```

That one pulls in `onnxruntime` + `scikit-image` + `numba` — a few
hundred MB — so it's kept optional.

## Making the clips

The reference "Aakash (3D)" look in the demo video is a pre-rendered
3D/Pixar-style character — that can't be generated by code, it has to come
from real video clips. The recipe:

1. **Create one consistent character image first.** A 3D cartoon version
   of yourself (or whoever), full body, on a **solid green background**
   (`#00FF00`), front-facing, neutral pose, good even lighting with no
   hard shadows on the green itself (shadows make chroma-keying ragged).
   Keep this one reference image and reuse it for every clip below so the
   character stays visually consistent across states.

2. **Generate one short clip per state** using any image-to-video AI tool
   (the exact tool doesn't matter — Runway, Pika, Kling, Sora, etc. all
   work), feeding in the reference image each time. Keep every clip:
   - **Locked camera** — no camera movement, same framing every time
   - **Same solid green background** — the same shade of green across
     all clips
   - **2-4 seconds long**
   - **Character facing the camera**, except the walk clip (side-on, so
     it reads correctly as walking left/right across the screen)

3. **Export each as its own `.mp4`.**

### Prompts to use for each clip

Swap `{character}` for a description of your reference image (e.g. "a
cheerful 3D cartoon avatar of a young man with short black hair, wearing
a blue hoodie").

| Clip | Prompt |
|---|---|
| `walk` | "{character}, walking sideways from left to right across frame, locked camera, solid green background, full body visible, smooth natural walk cycle, 3 second loop" |
| `idle` | "{character}, standing facing camera, relaxed idle breathing sway, slight weight shift, locked camera, solid green background, loopable, 3 seconds" |
| `ask` | "{character}, facing camera, head tilted slightly, curious questioning expression, one hand gesturing outward as if asking a question, locked camera, solid green background, loopable, 3 seconds" |
| `drink` | "{character}, facing camera, happily drinking from a water bottle held in both hands, pleased expression, locked camera, solid green background, 2-3 seconds, not loopable (clean start and end pose)" |
| `shrug` | "{character}, facing camera, shrugging shoulders with both palms up, apologetic friendly expression, locked camera, solid green background, 2 seconds, not loopable" |
| `sad` | "{character}, facing camera, shoulders drooping, disappointed but gentle expression, slow downward head tilt, locked camera, solid green background, 2 seconds, not loopable" |
| `wave` | "{character}, facing camera, waving one hand at the viewer, friendly smile, locked camera, solid green background, 2 seconds, not loopable" |

The "loopable" clips (`idle`, `ask`) should start and end on roughly the
same pose — `make_pack.py` detects the best loop point automatically, but
it works best when the source clip already loops cleanly.

## Running the tool

```
./tools/.venv/bin/python tools/make-pack/make_pack.py \
  --name "Aakash (3D)" --id aakash-3d \
  --clip walk=clips/walk.mp4 \
  --clip idle=clips/idle.mp4 \
  --clip ask=clips/ask.mp4 \
  --clip drink=clips/drink.mp4 \
  --clip shrug=clips/shrug.mp4 \
  --clip sad=clips/sad.mp4 \
  --clip wave=clips/wave.mp4 \
  --height 420 --fps 24 --bg auto
```

All seven `--clip` names are required (the `walk` clip is reused for both
the walk-in and walk-out states). Flags:

- `--name` — display name shown in the Character tab's gallery
- `--id` — pack id, lowercase-with-dashes, becomes the output folder name
  under `packs/<id>/`
- `--height` — target character height in px (default 420, matching the
  built-in packs)
- `--fps` — target frame rate (default 24)
- `--bg`:
  - `auto` / `colorkey` (default) — chroma-keys out `#00FF00` green with
    edge despill, for clips made on a green screen per the recipe above
  - `rembg` — ML-based background removal, for clips that aren't on a
    clean solid color (needs the optional dependency above; much slower)
  - `none` — clips are already transparent/pre-keyed, skip removal
- `--out` — output directory (default `packs/<id>`)

The tool prints progress per clip, the shared crop box it computed, any
detected loop seams, and the final pack size — with a warning if it's
over 15 MB (consider shorter clips, a lower `--fps`, or a smaller
`--height` if that happens).

Once it's done, the pack is both a ready folder under `packs/<id>/` (so
it shows up immediately in the app's Character tab in dev) and a zipped
`packs/<id>.zip` (ready to share or import via the Character tab's
"Import pack" button on another machine).

## How it works, briefly

1. **Extract** — each clip's frames are pulled out at the target fps via
   ffmpeg, with chroma-key + despill filters applied during extraction if
   `--bg auto/colorkey`.
2. **Remove background** (if `--bg rembg`) — each frame goes through
   `rembg`'s ML segmentation model instead.
3. **Shared crop box** — every frame across every state is scanned for
   its non-transparent pixel extent, and the union of all of them becomes
   one shared crop box. This is what keeps the character from jittering
   or jumping in size when switching between states — everything is
   cropped to the exact same rectangle.
4. **Resize + export** — each frame is cropped to that box, resized to
   `--height` px tall, and saved as WebP (quality 80, alpha preserved).
5. **Loop seam detection** — for the two looping states (`idle`, `ask`),
   the frame most visually similar to frame 1 is reported as the likely
   loop point (useful if you want to manually trim the source clip
   tighter; the tool doesn't auto-trim since that risks cutting a
   not-quite-perfect AI-generated loop awkwardly).
6. **Manifest + zip** — writes `pack.json` matching the schema the app's
   pack loader expects, then zips the whole folder.
